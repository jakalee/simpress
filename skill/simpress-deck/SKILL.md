# simpress 발표자료 제작 (작업지시서 → 완성 덱)

사용자가 작업지시서(또는 비슷한 요청)로 자료를 주면, [simpress](https://github.com/jakalee/simpress) 편집기로 두 가지를 만든다.
- **바로 발표하는 HTML**: 파일 하나로 열리고, 오프라인에서도 동작한다.
- **편집용 JSON**: simpress에서 열어 계속 고친다.

디자인은 다크 테크다. 어두운 그라데이션 배경, 유리 카드와 아이콘, 움직이는 흐름선, 순차 등장 효과, 슬라이드 사이 3D 이동, 발표자 노트(주 언어 + 번역)가 들어간다.

## 도구 (이 스킬 폴더의 `deckgen/`)

| 파일 | 역할 |
|---|---|
| `deckgen/art.js` | 배경·유리 카드·알약·흐름 화살표·아이콘 SVG 생성기. 그대로 재사용 |
| `deckgen/build.js` | `node build.js <덱 폴더>`. simpress 편집기를 Playwright로 열어 덱을 만들고 JSON·HTML 저장 |
| `deckgen/shots.js` | `node shots.js <덱.html>`. 장마다 스크린샷과 전체 보기 저장(검수용) |
| `example/` | 4장짜리 예제 덱. 새 덱은 이 폴더를 복사해서 시작 |

스킬 폴더에 `deckgen/`이 없으면 내려받는다.
- 저장소 통째로: `git clone https://github.com/jakalee/simpress` → `skill/simpress-deck/`
- 파일만: `https://jakalee.github.io/simpress/skill/simpress-deck/deckgen/art.js` (`build.js`, `shots.js`, `example/*`도 같은 주소 규칙)

필요 환경: Node 18+, `npm i playwright` 후 `npx playwright install chromium`.
- 편집기 위치는 이 순서로 찾는다: 환경변수 `SIMPRESS_EDITOR` → `deck.config.json`의 `"editor"` → 스킬 폴더의 `deckgen/editor.html`(zip 패키지에 들어 있음, 오프라인 가능) → `https://jakalee.github.io/simpress/index.html`.
- 오프라인이거나 로컬 편집기를 쓰려면 `deck.config.json`의 `"editor"`에 경로를 넣거나, 환경변수 `SIMPRESS_EDITOR`를 지정한다.

## 1. 작업지시서 양식

빠진 항목은 기본값으로 진행하고, 어떤 기본값을 썼는지 결과 맨 위에 밝힌다.

```
[발표 주제]
[청중·목적]        예) 외국 고객·파트너 대상 기술 소개
[언어]             슬라이드: 영어 / 노트: 영어 + 한국어 번역
[분량]             예) 20분, 10장
[자료]             주자료(pptx/pdf/문서), 사례, 다이어그램(svg/png), 영상(mp4 또는 링크), 참고용 기존 자료 — 각각 경로
[발표자]           이름 · 소속 · 팀
[디자인]           기본: 다크 테크(네이비 + 청록·보라·주황·민트)
[저장 위치]
[기타]             꼭 넣을 것 / 뺄 것 / 마감
```

기본값:
- 장 수 = 분량(분) ÷ 2
- 노트 = 슬라이드 언어 + 한국어 번역
- 영상 = 로컬 mp4 우선. YouTube는 제목·로고가 붙고 오프라인에서 재생되지 않는다.

## 2. 진행 순서

1. **접근 확인**: 모든 자료가 읽히는지 먼저 확인한다. 연결이나 승인이 필요하면 시작 전에 한 줄로 알린다. 흩어진 파일은 한 폴더로 모으면 편하다.
2. **자료 읽기** (3절). 사례 PDF와 이미지는 반드시 눈으로 본다.
3. **구성안**: 장마다 제목, 핵심 메시지 한 줄, 시각 요소, 쓸 자료를 정한다.
   - 자료에 없는 수치나 주장은 만들지 않는다.
   - 개념도나 업체 수치는 "concept illustration" 등으로 표시한다.
   - 남의 사례는 발표자·소속·행사·날짜를 슬라이드에 적는다.
4. **발표자 노트**: 한 장에 약 2분(영어 200~230단어), 그대로 읽을 수 있는 구어체로 쓴다. `notes.js`에 `[주 언어, 번역]` 형태로 넣으면 빌더가 `— 한국어 —` 구분선으로 잇는다.
5. **빌드**: `example/`을 새 폴더로 복사한 뒤 아래 세 파일을 쓰고 `node deckgen/build.js <새 폴더>`를 실행한다.
   - `deck.config.json`: 제목, 출력 이름, 파일 목록(경로, MIME, 원본 가로·세로)
   - `slides.js`
   - `notes.js`
6. **검수** (5절): `node deckgen/shots.js <폴더>/out/<이름>.html`. 모든 장을 직접 보고 고친 다음 다시 빌드한다.
7. **전달**: HTML과 JSON을 저장 위치에 둔다. 끝에 구성 표와 발표 전 확인할 점(출처 허락, 소개 문장, 파일 크기, OS별 글꼴 차이)을 알린다.

## 3. 자료 읽는 법

- **pptx**: zip을 풀어 `ppt/slides/slideN.xml`의 `<a:t>`를 문단(`<a:p>`)별로 모은다. 이미지는 `ppt/media/`에 있다.
- **pdf**: 페이지를 PNG로 렌더링해서 본다.
  - 맥: JXA와 PDFKit으로 `page.thumbnailOfSizeForBox` → PNG
  - 그 밖: `pdftoppm`, PyMuPDF, 또는 브라우저의 pdf.js
- **svg**: 브라우저로 스크린샷을 찍어 모양을 보고, `>텍스트<`를 추출한다. 원본 비율 그대로 `imgfile`로 넣는다. SVG 안의 애니메이션도 그대로 동작한다.
- **영상**: `ffprobe`로 크기와 길이를 보고, 프레임 몇 장을 뽑아 내용을 확인한다. 노트에는 영상 속 질문과 답을 정확히 반영한다.
- **기존 simpress HTML**: `<script id="zc-data">` 안의 JSON을 읽어 객체 목록만 참고한다.

## 4. slides.js 쓰는 법

좌표는 슬라이드 기준 픽셀이다. 캔버스는 1920×1080, `L/T/W/H` = 왼쪽, 위, 폭, 높이. `example/slides.js`의 도우미를 그대로 쓴다.

- `bg(n, 강조1, 강조2, extraSVG)`: 전체 배경. 흐르는 빛, 격자, 모서리 브래킷, 푸터, 진행바가 들어 있다. 흐름 화살표(`flow`)나 쉐브론처럼 위치가 고정된 도식은 `extraSVG`로 배경에 넣는다.
- `header(키커, 제목, 부제, 색)` 위치:

  | 요소 | y | 크기·굵기 |
  |---|---|---|
  | 키커 | 92 | 22 |
  | 제목 | 128 | 62 / 800 |
  | 부제 | 214 | 27 |

  본문은 y≈290에서 시작해 1000 안에서 끝낸다(푸터선 1012).
- `img(card(w,h,색,{icon,num}), L,T,W,H)` 위에 `txt(...)`를 올린다.
  - 글자는 항상 네이티브 `txt`로 둔다. 그래야 편집과 번역이 된다.
  - 장식과 도식은 SVG로 그린다.
- `txt(html, L,T,W, fs, 색, {fw, align, font:'mono', enter, vc})`
  - `vc: 높이`를 주면 그 높이 상자 안에서 세로 가운데 정렬된다(카드·알약 안 글자).
  - html에는 `<b> <br> <span style>`를 쓸 수 있다.
- 원본 그림: `{ t:'imgfile', file:'키', L,T,W,H, radius }`. 원본 비율을 지키고, 흰 배경 그림은 밝은 패널 카드 위에 올린다.
- 영상: `{ t:'video', file:'키', L,T,W,H }`. 컨트롤바는 숨겨지고 클릭하면 재생·일시정지된다.
  - 자동 재생: 같은 장의 그림에 `enterCode: "var v=document.querySelector('.o-video video');if(v){v.currentTime=0;v.play();}"`를 단다.
  - 앞뒤 장에는 빈 `txt`에 `...pause()` 코드를 단다.
- 등장 효과: `enter: 'fade'|'up'|'left'|'zoom'`(배경은 `null`). 넣은 순서대로 나오고, 전체가 1.6초 안에 끝나도록 자동으로 압축된다.
- 색: cyan `#33E7FF`, violet `#B960FF`, amber `#FFB454`, mint `#5DFFB2`, 본문 `#EAF2FB`, 보조 `#9FB3C8`, 흐림 `#5E7591`.
- 자주 쓰는 배치:
  - 카드 N열: 1680 폭을 나눔. 4열은 402 + 간격 24.
  - 좌우 2패널: 각 825, 간격 30.
  - 레인 표: 라벨 300 + 셀 3개.
  - 숫자 타일: 숫자 50px / 800.
  - 알약 줄: 폭 ≈ 16 + 글자수 × 10.6 + 24, 1800을 넘지 않게.
- 슬라이드 배치는 빌더가 자동으로 정한다. 4장씩 지그재그로 줄을 놓고 깊이와 기울기를 줘서, 전체 보기가 화면을 채운다.

## 5. 검수 체크리스트

- `shots.js` 결과를 전부 본다. 장마다 3.6초를 기다린 뒤 찍는다.
- 확인할 것:
  - 글자 넘침이나 겹침. 좁은 카드 제목이 두 줄이 되면 줄이거나 폭을 늘린다.
  - 부제와 그 아래 요소의 겹침
  - 알약 줄의 오른쪽 넘침
  - 이미지 비율 왜곡
  - 배경 사진 때문에 글자가 안 읽히지 않는지(덮개 불투명도 .86 정도)
  - 전체 보기 모양
- 실제 발표 PC 글꼴로 2~3장 다시 확인한다. 리눅스와 맥·윈도우는 글꼴 폭이 다르다. 크롬 헤드리스 예: `chrome --headless=new --window-size=1600,900 --virtual-time-budget=6000 --screenshot=s4.png "file:///…/deck.html#/step-4"`
- 영상: 해당 장에서 재생되고 앞뒤 장에서 멈추는지, 파일 크기는 얼마인지.
- 노트: 장 수와 맞는지, 원자료와 맞는지, 근거 없는 수치가 없는지.

## 6. 주의

- 사례와 도식의 출처를 슬라이드와 노트에 적는다. 외부 발표 전에 원저자 허락을 받으라고 알린다. 한국 이름의 영문 표기는 임의로 정한 것이라고 알린다.
- 회사·발표자 소개 문장은 사용자가 확인해야 할 항목으로 따로 짚는다.
- 결과 HTML에는 모든 그림과 영상이 들어간다. 영상이 있으면 수십 MB가 된다.
